# 检查清单

用户只会看成片，看不到过程。所以每个问题都要在交付前被你自己发现。

## 1. 每个镜头做完后（第 7 步）

用 `capture_frames.mjs --stills` 出开头、中间、结尾三帧，逐张看：
- [ ] 主体在画面里，没有被裁掉，没有贴边（离边缘至少 7%）
- [ ] 文字没有溢出，没有重叠，没有进入底部字幕区；字号不小于画面高度的 1/24
- [ ] 颜色、字体、角标符合 `style.json` 的规定，主色不超过三种
- [ ] 画面讲的就是这几句口播在讲的事。核对一下口播说到 X 的那一刻，画面上 X 是否已经出现或者高亮
- [ ] 读数和标注的数字和事实表或计算模型一致
- [ ] 证据角标正确：宣称、估算、复原想象、模拟、AI 生成画面
- [ ] 这一帧和前后镜头接得上（匹配剪辑的话，比较一下首尾帧）
- [ ] R1 镜头：零件没有互相穿过；放大 4 倍看，细节没有缺失

## 2. 样片（第 6 步）和成片（第 9 步）

```sh
bash scripts/contact_sheet.sh out/final.mp4 check/final 5     # 每 5 秒一帧，拼成 3×3 的接触表
```

**一定要从 MP4 文件本身抽帧来检查**，不能只看场景的截图。看完所有接触表，再看脚本打印出的技术指标：
- [ ] **时长**：在要求时长的 ±10% 以内
- [ ] **黑帧**：没有意外出现的黑帧（`black_start`），片头和片尾故意留黑的除外
- [ ] **定格**：没有超过 4 秒的画面静止（`freeze`），除非这个镜头本来就是静止的。如果有，通常是片段比时间轴短、被补帧补长了
- [ ] **响度**：整体约 −16 LUFS，峰值低于 −1 dBTP
- [ ] **音画同步**：随机抽 5 个时间点，用 `ffmpeg -ss <t> -i out/final.mp4 -frames:v 1 check/at_<t>.png` 截图，再对照 `audio/timeline.json` 看那一刻在说哪一句，画面和口播是否一致
- [ ] **字幕**：每行不超过规定字数，没有错别字，和配音内容一致（读音修正的句子显示原文）
- [ ] **开头**：前 3 秒（竖版）或前 8 秒（横版）就出现了问题或最强的画面
- [ ] **结尾**：回答了开头的问题

## 3. 内容核对

- [ ] `script.md` 里每个 `{F..}` 都能在 `research/facts.md` 里找到，并且带来源
- [ ] C、D、E、R、S、G 等级的内容，口播的说法和画面角标都体现了等级
- [ ] 人物引语都有出处，没有编造的话
- [ ] `brief.md` 里“必须讲清的 3–5 件事”，片子里都讲到了
- [ ] 有时效性的内容，标明了研究日期

## 4. 素材核对（见 `rights.md`）

- [ ] `research/assets.md` 里登记了每一个外部素材（图片、视频、音乐、音效、字体）的来源和授权
- [ ] 需要署名的素材，署名出现在画面上，或者写在片尾
- [ ] 没有真实人物的 AI 生成形象或克隆声音
- [ ] 没有用受版权保护的角色或商标做主画面

## 5. 交付说明怎么写

交付时告诉用户这些内容（简短即可）：
1. 成片路径；竖版剪辑和交互页（如果有）的路径。
2. 片长、画幅，以及在 `choices.md` 里记录的选择。哪些是用户选的，哪些是按推荐默认的。
3. **哪些地方没有核实或者是估算的**，具体到条目。
4. 需要用户自己处理的事：替换占位配音、确认授权、补充署名等。
5. 工程目录在哪里，以及怎么修改。例如：改某一句的口播，只需重新生成那一句的配音，然后依次运行 timeline、受影响的镜头和 assemble。
