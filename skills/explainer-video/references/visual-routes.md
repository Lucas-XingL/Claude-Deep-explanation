# 视觉路线 R1–R9

所有路线都要遵守下面几条：
- 颜色、字体、角标统一用 `style.json` 里的设定；
- 每个镜头的输出都是 `scenes/<id>/clip.mp4`；
- 运动都按时间 t 计算；
- 所有数字从事实表或计算模型里读取。

给某条路线写画面提示词（不管是给自己还是给其他模型）时，按这个顺序写：
1. **整体风格**
2. **画面里必须有的东西**
3. **怎么动**：从哪出发、经过哪、停在哪；什么时候发生什么
4. **不能出现的东西**

## 和 R1 搭配的纸面风 2D 场景

anatomy 镜头讲“它长什么样、怎么拆开”，原理、受力、推导和计数交给 2D 场景讲。两支样片都是这样搭配的：机械表是“3D 机芯 + 2D 擒纵俯视图”，Roadster 是“3D 跑车 + 2D 推力测力台”。

- **外观要统一**：用 `templates/scene-paper.html` 加 `paper.css`，纸面底色、图框、Fig 编号、角落里的等宽小字都和 anatomy 镜头一致。观众会觉得是同一本书里的两张图。
- **同一个物体**：2D 里要出现同一辆车或同一块表时，用 `scripts/anatomy/sprite.sh` 从模型抠出贴图，不要另外重画。
- **同一个模型**：2D 场景读 `scenes/_shared/model.js`。机械表的 2D 擒纵和 3D 机芯用的是同一个 `movement(tau)`，所以两边的节拍、摆幅、齿轮步进完全一致。
- **慢放而时间连续**：机器太快时（摆轮每秒摆 8 次），场景里用“机器时间” `tau` 而不是画面时间 `t`。`tauAt(t)` 对慢放倍数积分，所以可以在讲某一句时更慢（样片在讲“冲击”时从 1/16 再放慢到 1/48），而 `tau` 不会跳。把当前的慢放倍数写在右下角的读数里。
- **跟着口播出现**：零件名在被说到时淡入（`atLine`），高亮和箭头只在那句话期间出现（`during`），计数器从那句话开始计。
- **证据角标**：数字旁边挂上“宣称：超过 80 kN”“估算：1700 kg × g”“示意”。

## R1 剖解等距（anatomy）

- **适合**：
  - 物体和机构：产品、发动机、手表、铰链、火箭；
  - 用“真实物体”来比喻抽象过程。
- **做法**：见 `anatomy-route.md`。
  - 安装了 anatomy 或 anatomy-reveal 的话，直接用它们；
  - 没有安装，就用 Three.js 按同样的原则做：真实尺寸、按装配关系分组、能拆开、特性零件会动、读数来自模型。
- **母版资产**：一个可以拆开、能动的主体模型。全片的多个镜头都从它取景：整体、特写、拆开、剖面、某个特性在动。
- **常见坑**：
  - 画成方框加箭头；
  - 零件之间相互穿插；
  - 尺寸是编的；
  - 画了品牌 logo。

## R2 信息动效（motion graphics）

- **适合**：数据卡、宣称与证实对照、文字重点、产品界面、标题、章节卡。
- **工具**：
  - 简单的镜头直接从 `templates/scene.html` 改（Canvas 2D 或 HTML/CSS），用 `capture_frames.mjs` 渲染；
  - 多镜头、组件化的工程用 **Remotion**（`npx create-video@latest`，渲染命令 `npx remotion render <id> out.mp4`）。时长和帧率从 `timeline.json` 读取；
  - 复刻参考视频：把参考片交给模型，让它“把这段视频反向拆解成 HyperFrames（或 Remotion）代码”。HyperFrames 是一个从网页做视频的工具。复刻的是节奏和构图，不能照搬原片的素材和品牌。
- **美术规则**（来自对常见 AI 产品片的总结）：
  - 不要用“居中大字 + 渐变背景 + 所有东西一起淡入”这种模板；
  - 主色最多三种；
  - 一屏只讲一个重点；
  - 元素按顺序进场，跟着口播出现；
  - 留白要足。
- **常见坑**：文字太多；所有元素同时出现；字号太小（不小于画面高度的 1/24）。

## R3 板书推导（Manim）

- **适合**：
  - 公式、几何关系；
  - 物理量估算，比如推重比、能量账、分辨率和口径；
  - 概率分布、曲线，比如烘焙曲线、摆轮的振荡。
- **工具**：`pip install manim`（需要 LaTeX 才能渲染公式，没有的话用 `Text` 代替 `MathTex`）。
  - 渲染命令：`manim -qh --fps 30 -r 1920,1080 scene.py SceneName`，输出在 `media/videos/` 下，拷贝到 `scenes/<id>/clip.mp4`；
  - 和口播对齐：在 Manim 场景里读取 `audio/timeline.json`，用对应句子的时长做 `self.wait()` 和 `run_time`。
- **风格**：背景用 `style.json` 里的 paper 色或深色版，不用 Manim 默认的黑底蓝字。
- **常见坑**：公式一次全部出现。应该一步一步推导，每一步对应一句口播。

## R4 地图与路线

- **适合**：产地、运输线、观测站分布、航线、历史上的行进路线。
- **工具**：
  - Canvas 2D 或 SVG，配合 d3-geo 投影（`d3.geoNaturalEarth1()` 等）；
  - 地图底图用公共领域数据，比如 Natural Earth，也可以用 world-atlas 的 TopoJSON；
  - 本地 HTML 不能用 fetch 读取 file:// 文件，所以把数据内联进 HTML，或者在 HTML 旁边放一个 `.js` 文件，以 `window.DATA = …` 的形式加载。
- **同步**：路线的延伸进度绑定到口播句子上（`onLine(t, "L012")`），“说到哪，线就画到哪”。
- **常见坑**：地图上的文字太多；投影把关键区域挤得太小（应该先放大到相关区域）。

## R5 3D 场景（Three.js，加 Blender）

- **适合**：空间感和尺度、运镜、环境、轨道，以及需要写实材质的产品。
- **工具**：
  - Three.js 写在 HTML 里，`renderFrame(t)` 里设置相机和物体状态后调用 `renderer.render()`；
  - 创建 renderer 时开启 `preserveDrawingBuffer: true`，截图才不会是空白；
  - 复杂模型用 Blender 建好后导出 glTF，再用 Three.js 加载。也可以直接用 Blender 渲染：`blender -b scene.blend -a`；
  - 模型可以让 AI 写 Blender Python 脚本来生成。
- **运镜**：只描述“从哪出发、经过哪、停在哪”，用样条曲线插值相机位置和朝向，看向的目标也要插值。
  - 不懂运镜术语的话，可以先用第一人称视角走一遍，或者模拟无人机视角；
  - 写成 `camera(t)` 函数，不要实时跟随鼠标。
- **常见坑**：
  - 用了 `clock.getDelta()`，导致运动依赖真实时间（应该用 t）；
  - 无头浏览器里 WebGL 太慢：先用小尺寸预览，确认后再出高清；
  - 模拟画面没标“模拟”。

## R6 手绘和水彩

- **适合**：历史和人物故事（用插画，避开肖像授权问题）、科学复原、轻松的科普风格。
- **工具**：
  - 手绘线条用 Rough.js（`roughness`、`bowing` 控制抖动程度）；
  - 水彩和水墨用 p5.js 加 p5.brush，在 `noLoop()` 模式下，由 `renderFrame(t)` 调用 `redraw()`；
  - 笔触的随机性用固定种子（`randomSeed(42)`），每一帧笔触的“抖动”也由 t 决定。capture 脚本已经固定了 `Math.random` 的种子；
  - 角色设计：先出一张角色设定表（各个角度、表情、动作），写成可以复用的绘制函数，所有镜头都调用它。
- **常见坑**：
  - 每一帧笔触都完全随机，画面会闪烁。要么固定笔触，只让局部动；要么用“每 3 帧换一次”的手绘抖动；
  - 复原画面没标“复原想象”。

## R7 档案和实拍素材

- **适合**：真实的人物、事件、生产场景、历史影像。
- **素材来源**：
  - 公共领域（比如大部分 NASA 影像）；
  - CC 协议素材（标明署名）；
  - 授权图库；
  - 用户提供的素材。
  
  逐条登记到 `research/assets.md`（见 `rights.md`）。
- **做法**：
  - 照片用 Ken Burns 推拉（HTML 场景里用 `transform: scale/translate` 随 t 变化），配合代码叠加层：标注、时间线、地图小窗、数据；
  - 视频素材用 ffmpeg 裁剪出需要的片段（`-ss -t`），统一色调（`eq`、`colorbalance`），放到 `scenes/<id>/clip.mp4`，需要叠加层的话再合成一次。
- **常见坑**：
  - 素材画质参差不齐：统一加轻微的颗粒或调色；
  - 素材内容和口播对不上；
  - 用 AI 生成的画面冒充档案。

## R8 视频模型补镜头

- **适合**：代码很难画的连续真实动作，比如生物运动、液体、人的动作、风格迁移转场。
- **规则**：
  - 只用于代码画不了的镜头，全片占比建议不超过 20%；
  - **全程标注“AI 生成画面”**；
  - **不能用来生成真实人物**（库克、宇航员、具体的咖啡农），也不能冒充纪录影像；
  - 提示词按“整体风格 → 必须有的东西 → 运动 → 不能出现的东西”来写，画风要和全片一致；
  - 每个镜头生成后，检查首尾帧，确认能和前后镜头接上。
- **分工**：精确的文字、数字、图表交给代码；连续的动作交给视频模型；最后拼进同一部片子。
- **常见坑**：出现手指、文字之类的瑕疵；画风和其他镜头跳脱；时长不可控（多生成几段，挑最好的再裁剪）。

## R9 时间线和图谱

- **适合**：企业史、人物生平、地质年代、决策树、多因素关系。
- **做法**：
  - 一条贯穿全片的时间线作为母版资产，每个转折是时间线上的一站，镜头沿着时间线移动；
  - 地质年代这类跨度大的时间线要按比例画，用来破除“霸王龙和剑龙是同时代的”这种误解；
  - 决策树：每个节点画出当时的几个选项，选中的那条亮起，没选的变暗但保留，让观众看到“当时还有别的路”。
- **常见坑**：节点太多，变成罗列。只保留 3–5 个关键转折，其余的变暗或者省略。

## 镜头之间的转场

转场在场景内部做，合成时一律硬切（见 `render.md`）：
- **匹配剪辑**：前一个镜头最后一帧的主体位置，等于后一个镜头第一帧的位置。
- **动作带入**：人物走进一扇门，门后就是另一种画风；零件被推出画面，进入下一个场景。
- **推进或拉远到细节**：用 R1 和 R5 镜头的机位连续变化来完成。
- 避免随意使用溶解和闪白。
