# 题型识别与选择卡

## 1. 先判断题型

一个选题可能同时属于两种题型。取**主题型**决定叙事骨架，**副题型**用来补镜头。

| # | 题型 | 识别信号 | 叙事骨架 | 推荐主路线 | 常配的辅助路线 | 主要风险 |
|---|---|---|---|---|---|---|
| T1 | 新品研究与结构解释 | 新款、发布、拆解、“有什么特别” | 它是什么 → 和旧方案比特别在哪 → 结构拆开看 → 难点逐个讲 → 代价与取舍 | R1 剖解 | R2 数据卡、R5 3D | 时效性；传闻当事实；商标 |
| T2 | 工程原理与传播表达 | 设计原理、怎么做到的、“便于传播” | 一个惊人的宣称 → 物理上需要满足什么 → 拆开看各系统怎么满足 → 算一笔账 → 还不知道的 | **R1 剖解（固定）** | R3 推导、R2 宣称与证实对照 | 宣称多、证据少；数字来源 |
| T3 | 人物与企业纪录片 | 某人时代、卸任、纪念、“讲选择” | 接手时的局面 → 3–5 个关键选择（每个讲当时的选项、为什么、代价）→ 这些选择怎样落到普通人身上 → 留下的问题 | R7 档案 | R9 时间线、R2 数据卡 | 真人肖像；编造引语；褒贬失衡 |
| T4 | 开放选题与科学复原 | 介绍某类事物、“改变误解”、零基础 | 3–5 个误解，每个按“你以为 → 证据 → 现在的认识 → 仍不确定的地方”讲 | R6 手绘或水彩复原 | R5 3D、R8 视频模型（标注） | 复原当成定论；过时知识 |
| T5 | 精细机构与连续因果 | 为什么能一直走、零件怎样配合 | 从能量源开始，沿因果链一节一节传下去，每节只加一个零件 → 最后全链同时运转 | R1 剖解（3D 联动） | R3 推导（周期、比率） | 运动关系画错；齿比不真实 |
| T6 | 抽象过程可视化 | 它到底经历了什么、黑箱 | 用一个具体问题贯穿：输入 → 每一步的变换（同一个例子的真实中间态）→ 输出 → 为什么会错 | R2 信息动效，借 R1 的“物体比喻” | R3 概率分布 | 比喻失真；把模型拟人化 |
| T7 | 真实场景与过程叙事 | 旅程、从 A 到 B、真实的人和场景 | 按物理流程分站，每站讲：在哪、谁在做、发生了什么变化、这一步对最终结果有什么影响 | R7 实拍或授权素材 | R4 地图、R3 化学或曲线、R8（标注） | 假装实拍；素材授权 |
| T8 | 证据与科学边界 | 我们怎么知道、照片里到底是什么 | 看起来不可能 → 换个角度理解“看见” → 证据链一步步来 → 图里有什么、没有什么 → 边界与下一步 | R3 推导与 R2 图解 | R5 3D、R7 真实图像（授权） | 过度简化成错误；图像误读 |
| T9 | 历史事件与技术过程 | 跟着某人从开始到结束、关键步骤为什么必须这样 | 按时间顺序走，每个关键节点讲“如果不这样会怎样” | R7 档案（公共领域影像） | R5 3D 轨道或飞行器、R1 剖解 | 史实细节；神话化 |
| T10 | 商业故事与多因素解释 | 怎么从 X 变成 Y、转折、成功与失败 | 起点 → 每次转折（当时环境、可选路、选了什么、结果）→ 失败也讲 → 背后贯穿的逻辑 | R9 时间线或图谱 | R6 插画、R2 数据卡、R7 档案 | 事后诸葛；角色和商标版权 |

视觉路线 R1–R9 的具体做法见 `visual-routes.md`。

## 2. 哪些选题固定路线

满足下面任一条件，**视觉主路线固定，不再问**：
- 用户点名了路线或工具，比如“用 anatomy 做”“做成水彩风”。
- **T2 工程原理类，且用户要求用 anatomy 或类似方法。Roadster 属于这一类**，主路线是 R1，做法见 `anatomy-route.md`。

路线固定的选题，选择卡只保留“时长与画幅”“声音”两个问题；用户已经说过的也不再问。

## 3. 选择卡

### 规则
- **只在答案会改变研究对象或讲法时才问。** 先用一句话说出你对选题的理解，再给 2–3 个具体的方向让用户挑，不要让用户从一张空表开始填。比如“汽车电池”可以给：“电池怎么存电放电”“为什么热管理这么重要”“固态电池到底新在哪”。用户的说法已经够具体（比如 10 个示例选题），就不要再问内容方向。
- 文案、分镜、配音这些环节不再逐一确认，做完全片脚本和分镜后用方案页一次性确认（SKILL.md 第 6 步）。
- 一次最多问 4 个问题，每个问题 2–4 个选项，用户总能自己补充其他答案。
- 推荐选项放第一个，标签末尾写“（推荐）”。
- 每个选项的说明写清楚**选了之后片子会变成什么样**，以及代价（耗时、版权风险、真实感）。
- 用户已经给出的信息不再问。比如用户说了“5 分钟”，时长就不问，只问画幅。
- 在 Claude Code 里用 AskUserQuestion 工具。其他环境里按 `templates/choice-card.md` 的格式输出，然后停下来等用户回复。
- 无法交互，或用户说“你定”时，全部用推荐项，记进 `choices.md`。

### 四个标准问题

**Q1 视觉路线（问题标签：画面风格）**：从题型表的推荐主路线和辅助路线里组合出 2–4 个方案。每个方案写清“主路线加辅助路线”和一句画面描述。可以在说明里附上示例画面。

**Q2 时长与画幅（问题标签：时长画幅）**：
- 用户要求的时长，16:9 横版（推荐，适合 B 站、YouTube 和长讲解）
- 用户要求的时长 16:9，外加一条 60–90 秒的 9:16 竖版传播剪辑
- 只做 60–90 秒 9:16 竖版（适合小红书、抖音、视频号）

**Q3 声音（问题标签：配音）**：
- AI 中文配音加背景音乐（推荐）
- 只要字幕和音乐，不要配音
- 用户自己录音：先给脚本，用户录好后按录音对时间轴

**Q3 的音色选项**（edge-tts，已在样片中验证）：云希 zh-CN-YunxiNeural（男，平静讲述，推荐）、晓晓 zh-CN-XiaoxiaoNeural（女，温和）、云健 zh-CN-YunjianNeural（男，有力，适合传播片）。

**Q4 素材来源（问题标签：素材）**：
- 全部用代码生成（推荐，没有版权风险，风格统一）
- 混入真实影像：公共领域素材、授权图库或用户提供的素材（真实感强，需要核对授权）
- 允许用视频模型补连续动作镜头（会标注“AI 生成画面”，不用于真实人物）

T3、T7、T9 这类以真实影像为主的题型，Q4 的推荐项改为“混入真实影像”。

**Q4 也可以换成“确认方式”**：当素材来源已经确定（比如 anatomy 路线全部由代码生成），就把第 4 个问题换成：
- 先看方案页（推荐）：脚本、分镜、关键镜头的风格帧、试听和待确认事项放在一个网页里，确认后直接做全片；
- 先看 30 秒视频样片：每轮多花约一小时（配音、渲染、合成），适合特别在意节奏和配音效果的片子；
- 直接做全片：不停下来确认。

最早的两支样片问的是“先看样片”。后来默认改成方案页，因为样片每轮的配音、渲染和合成都要额外花时间，而讲法和画风在方案页上就能确认。多个片子一起做时，四个问题可以合并在一张卡里问（比如“机械表的画风”只针对其中一支，“时长画幅”同时适用于两支）。

### 写法示例（恐龙选题的 Q1）

```
问题：恐龙片的画面风格想要哪种？
- 水彩复原加 3D 骨架（推荐）：主路线 R6，辅助 R5。博物馆插画式的水彩复原，讲误解时切到可以转动的 3D 骨架，对比“老复原”和“新复原”。
- 3D 写实复原：主路线 R5，辅助 R8。电影感 3D 场景，连续动作用视频模型补，都标注“复原想象”。
- 手绘科普风：主路线 R6，辅助 R2。Rough.js 手绘线条加数据卡，轻松，制作最快。
```

## 4. 写进 choices.md

```
题型：T4（主）+ T8（副）
视觉：R6 水彩复原（主）+ R5 3D 骨架（辅）— 用户选择
时长画幅：5 分钟 16:9 + 75 秒 9:16 剪辑 — 用户选择
声音：AI 配音 zh-CN 男声，平静讲述 — 推荐默认（用户说“你定”）
素材：全部代码生成 — 推荐默认
确认方式：方案页
```
