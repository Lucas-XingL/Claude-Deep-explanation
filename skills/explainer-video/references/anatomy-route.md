# R1 剖解路线：anatomy 方法

用户要求用 anatomy 做的选题（比如 Roadster）必须走这条路线。用户选了 R1 的选题（比如机械表、折叠屏铰链、土星五号）也走这条路线。

## 1. 两个现成的 skill

| skill | 作用 | 在这里怎么用 |
|---|---|---|
| **anatomy**（[wheresryan22/anatomy](https://github.com/wheresryan22/anatomy)，MIT） | 等距 SVG 剖解图，可以交互，零件很多、很精细；带 WebGL 特效（火焰、尾焰、水、灯光）；有一套几何检查（`--audit`），保证零件互不穿插 | 学它的方法（第 2 节）；做**可交互的剖解网页**，可以作为额外交付物用于传播；尾焰之类的特效参考它的 `raptor-engine` 示例和 `references/webgl.md` |
| **anatomy-reveal**（[annnguyentt/anatomy-reveal-skill](https://github.com/annnguyentt/anatomy-reveal-skill)，MIT，基于 anatomy 的工具包） | 把一个物体按真实尺寸搭成可以转动、拆开的模型，输出**剖解揭示短片**（MP4，30 fps，3–60 秒，比例可选 9:16、4:5、1:1、16:9，纸面风格，带运动模糊） | **R1 镜头的主要生产工具**：每个 R1 镜头就是一段 anatomy-reveal 短片 |

安装（任选一种；Codex 等其他 agent 的安装目录见各自的 README）：

```sh
# anatomy
npx skills add wheresryan22/anatomy -g -a claude-code
#   或者 git clone https://github.com/wheresryan22/anatomy.git ~/.claude/skills/anatomy
# anatomy-reveal
git clone https://github.com/annnguyentt/anatomy-reveal-skill ~/.claude/skills/anatomy-reveal
```

依赖：Node.js 20+、Chrome 或 Chromium（找不到时设置 `CHROME_PATH`）、ffmpeg、ImageMagick 7（`magick`）。

**用之前先读它们的 SKILL.md 和 references**（anatomy 的 `craft.md`；anatomy-reveal 的 `inputs.md`、`objects.md`、`object.md`、`shots.md`），按它们的规则来做。本文件只讲怎么把它们接进讲解视频的流程。

如果这两个都装不上（比如没有网络），就按第 5 节用 Three.js 按同样的方法自己做，并告诉用户用的是替代方案。

## 2. 方法要点

1. **物体本身就是解释。** 不画方框加箭头，而是找一个真实、做工精良的物体，让它的运作方式本身就是要讲的概念。读者能认出这台机器，也就看懂了道理。
   - 讲“离地需要推力不小于重力”，就画一个推力试验台：车放在台上，秤和推力计的读数随推力变化。
   - 讲“齿比决定转速”，就画一对真实的齿轮（见 `examples/mini`）。
2. **先找真实数据。** 尺寸、数量、阈值、曲线都要真实。读数、运动和说明文字由同一个纯函数模型驱动。
3. **零件要多、要真实。** 每个零件都得有作用，并且安装在另一个零件上；不要为了好看加装饰。放大 4 倍看，每个区域都还有真实的细节可看。
4. **按真实的拆法分组。** 拆开的顺序就是这个东西在工作台上实际拆开的顺序，外面的零件先拆。
5. **一到两个特性零件真的会动。** 选这个东西最核心的动作，比如开合、旋转、按压、喷射。
6. **事先定好规模。**
   - Figure：40–80 个零件。
   - Hero：100–150 个零件，2–4 小时。
   - Epic：整辆车、整栋建筑这种级别，6 小时以上，不要直接做。先给用户一个 Hero 版本：保留核心，细节只花在镜头会推近的 2–3 个区域，其余部分做成干净的大零件。

## 3. 接入讲解视频

1. **规格单**：按 anatomy-reveal 的 `references/inputs.md` 写，包括尺寸、材料、会动的部分、内部结构、按装配关系分组的零件清单、特性零件。来源和证据等级同步写进 `research/facts.md`。
   - 不确定的尺寸要写明假设。
   - 有疑问的地方先给用户看规格单再动手。
2. **搭物体**：
   - `node <anatomy-reveal>/scripts/new-project.mjs scenes/_shared/<物体名>`；
   - `node <本 skill>/scripts/anatomy/setup_shots.mjs scenes/_shared/<物体名>`：生成按镜头构建用的 `motion/build-shot.mjs`；
   - 改 `object/geometry.mjs` 和 `object/film.mjs`，建模经验见第 5 节；
   - 每改一轮都运行 `node object/test-page.mjs --light`（报 interlock 就修），再用 `object/shots.mjs` 截几个角度看；
   - 收尾时从五个角度运行 `node object/scan-apart.mjs <yaw> <pitch>`，直到全部报告 “no pairs pass through each other”。
3. **每个 R1 镜头一个关键帧文件**：`shots/<id>.mjs`，从 `templates/anatomy-shot.mjs` 改。
   - `make(shot)` 拿到这个镜头在 `audio/timeline.json` 里的时长和句子时间，返回以秒为单位的关键帧。
   - 动作要挂在句子上：比如 `L.L002.start + 1.6` 开始翻转。
   - 节奏参考它的 `references/shots.md`：慢慢漂移、快速甩镜到下一个主体、短暂停留。
4. **渲染**（一条命令完成构建、并行渲染、编码、时长检查和导出检查帧）：
   ```
   bash <本 skill>/scripts/anatomy/render_shot.sh scenes/_shared/<物体名> scenes/_shared/<物体名>/shots/S01.mjs \
        audio/sample/timeline.json S01 scenes/S01/clip.mp4 --ratio 16:9 --jobs 3
   ```
   - 先加 `--stills-only` 看五张静帧，构图和时机都对了再正式渲染。
   - 正式渲染后，一定要看 `scenes/S01/clip.mp4.check.png`（从成片里抽的一帧）。
   - 片段没有声音，声音在 `assemble.py` 合成时统一加。
5. **2D 场景需要同一个物体时**（侧视图、图表里的小图标）：先用 `--no-plate` 构建一个页面，再运行 `bash <本 skill>/scripts/anatomy/sprite.sh <工程> motion/shots/<页面>.html '{"yaw":-90,"pitch":0,"zoom":2.4}' scenes/_shared/<物体>_side.png`。它用差值遮罩抠出透明背景的贴图，外观和 3D 镜头完全一致。
   **样片里踩过的坑**（前三条脚本已经处理，后三条要自己注意）：
   - `motion/render.mjs` 按位置取参数。`blur` 模式的第三个位置用不到，却会吞掉紧跟的参数，导致 `--page` 被静默忽略，渲染出来的是模板自带的咖啡机。`render_shot.sh` 会自动传一个占位符 `_`。
   - ffmpeg 不会自动建输出目录；系统里没有 `magick` 时，要改用 ImageMagick 6 的 `convert`。
   - 镜头时长和成片时长对不上，或者渲染失败了却没人发现。`render_shot.sh` 会对时长并导出检查帧。
   - 某个通道从片中才开始变化时，要在开始变化的那一刻写一个“保持原值”的关键帧（`{ t: x0, apart: 0 }`），否则它会从 t=0 开始插值，车一开场就是拆开的。
   - 特性通道不能和机位通道同名，比如车轮转动不能叫 `roll`，否则车轮的值会被当成镜头的滚转角。
   - 只看 `stills` 不够。`stills` 和 `blur` 用的参数解析不一样，静帧对不代表成片对，一定要看成片里的帧。
6. **标注和角标**：anatomy 风格要求画面里尽量少字（最多一个刻印小标签）。
   - 每个镜头的 `labels` 会显示在图框的左下（hint）和右下（readout）两个角，适合放零件名、读数、证据等级，比如 `{ hint: "宣称", readout: "“飞行汽车是真的”" }`，`{parts}` 等占位符会自动填入。
   - 更复杂的说明（箭头、推导）切到 2D 场景去讲，不要往 3D 画面里塞字。字幕负责其余的说明。
7. **额外交付可交互剖解页**：anatomy-reveal 的 `object/figure.html`，或者 anatomy 做的交互图。可以发到网上供观众自己拖动、拆解，很适合传播。
8. **默认不画商标**，零件用通用名称标注（电池组、电机、推进器）。用户明确要求忠实复刻时，才画品牌标识，并提醒商标风险（见 `rights.md`）。

## 4. Roadster 选题：样片的实际做法

样片工程在仓库的 `productions/roadster/`，研究日期是 2026-10-18。下面的结论**会过期**，再做之前要重新核实。

### 4.1 研究改变了讲法
- 开工时发布会三天前刚开过（2026-10-15）。公开演示的是：沿弯道开到倒挂、空中翻转落地、跳过一排车、0-60 英里 0.81 秒（特斯拉自己计时）。**没有持续飞行或悬停**，车上也没有真人。
- 推力（超过 80 kN）、气瓶（Rocket 版共 600 升）、气量（约 250 kg）、整车质量（不到 1,700 kg）都只是工程师在采访里说的，按 C 级处理。
- 所以全片的问题从“它怎么飞”改成了“它到底是怎么做到的？真的能飞吗？”，主线是：抓地力有上限 → 风扇把车吸在地上 → 推进器干脆不靠轮胎 → 算一笔气量账 → 它的“飞”只是几秒钟的跳跃。

### 4.2 数值模型（`scenes/_shared/model.js`）
- 车重 = 1,700 × 9.81 ≈ 16.7 kN；
- 抓地力极限：零到 60 英里 ≈ 26.8 /(μ·g)，按 μ = 1.4–1.8 估算为 1.5–1.95 秒；
- 平均加速度 = 26.8 / 0.81 ≈ 3.4 g；
- 冷气每牛顿推力每秒耗气 1/(Isp·g₀) ≈ 1.5 克（Isp 取 70 秒）；
- 悬停耗气约 28 kg/s，250 kg 气理想情况下约 9.6 秒（计入质量逐渐减少）。

口播里的“一万七千牛顿”“一点五克”“二三十公斤”“十秒左右”都来自 `report()`。

### 4.3 物体和场景
- **跑车剖解模型**，104 个零件，Rocket 配置：车身外壳、7 段轮拱、车门和侧裙、电池底板（盖板上画着 4680 电芯）、两台后电机、4 个车尾风扇、200 升和 400 升两个气瓶、4 个车尾喷口、4 个向下喷口、2 个侧向喷口。外观中性，不画品牌标志。
- **推力测力台**是一个 2D 场景，用的是从模型抠出来的侧视贴图：车尾推力涨到“宣称 80 kN” → 显示车重线 → 向下喷口点火，推力超过车重时测力台读数归零，车离地。
- 钩子镜头：开进来 → 绕车身长轴翻转一周（在侧视角度下改 pitch，就等于车绕自己的长轴转）→ 英雄镜头配“宣称”角标 → 拆开，露出气瓶和喷口。

### 4.4 全片分镜（约 3 分钟，16:9）
| 段落 | 路线 | 画面 |
|---|---|---|
| 钩子 | R1 | 翻转、宣称角标、拆开（样片 S01） |
| 先分清楚 | R2 | 已演示、宣称、未知三栏，加三个版本（风扇、车尾推进器、四周推进器） |
| 抓地力的天花板 | R3 | 摩擦上限公式；1.5–1.95 秒对 0.81 秒；平均 3.4 g |
| 风扇吸地 | R1 加 R3 | 车尾风扇转动、侧裙放下；车底负压箭头；倒挂在弯道上（贴图旋转） |
| 推进器 | R1 加 R3 | 拆开露出气瓶和喷口；一万 psi 约等于胎压的 300 倍；测力台（样片 S02） |
| 算一笔账 | R3 | 每秒耗气、气瓶读数下降、约十秒；联邦航空局的表态 |
| 还不知道的 | R2 | 量产车重量、电池、补气时间、上路资质 |
| 收束 | R1 | 英雄镜头 |

### 4.5 传播版本
- **9:16 竖版，60–90 秒**：前 3 秒直接给翻转或喷射加上问题，只保留“推力大于重力”和“能飞多久”两段，字幕烧进画面，结尾停在英雄镜头。
- R1 镜头用 `--ratio 9:16` 重新渲染，不要从横版裁切；2D 场景按 `SCENE.width` 和 `SCENE.height` 重新排版。
- 封面：英雄镜头的一帧，加一行问题（不超过 12 个字）。

## 5. 建模经验（机械表和跑车两个模型）

### 5.1 先规划，再写零件
- **先列一张 z 层规划表**（机械表这种扁平物体）或分区表（跑车），写清每类零件占哪个高度区间：表盘、主夹板、轮系、擒纵、摆轮、夹板、摆陀、后盖。大部分穿插（interlock）都是两个零件在同一高度、平面上又重叠造成的。
  - 啮合的齿轮和齿轴必须在同一高度，并且刚好相切（中心距 = 两半径之和 + 0.05）。
  - 不啮合、但平面上重叠的轮子，要错开到不同高度。比如中心轮和发条盒重叠，就把发条盒整体抬高，下面垫一根轴。
- **布局用数值求解**：齿轮链从中心出发，按“中心距 = 半径和”逐个放；摆轮、发条盒要整个落在夹板内。写个小脚本，试几组角度，选出都不出界、间隙为正的那组（`productions/watch` 的 `LAYOUT`）。
- **先把机构跑对，再加细节**：先用 `film.mjs` 里的运动模型验证速比，比如四轮每分钟 360°、中心轮每小时 360°、每秒 8 拍，再去画螺丝、宝石和条纹。

### 5.2 只能用凸零件，常用的办法
- **圆环**（摆轮外缘、表壳、轮拱）：扇环用“内侧弦 + 外侧弧”的多边形拼。注意内侧弦的中点比内半径更靠里，所以相邻的零件要按 `r·cos(半个扇形角)` 留出余量。
- **不规则的板**（夹板、摆轮夹板）：在每个轴的位置放一个小圆，求凸包（`blob(points, r)`）。
- **车身**：分区做。侧面用 yz 平面的多边形沿 x 拉伸，轮拱 7 段，车头和车尾的角块单独做，中间的发动机盖、风挡、车顶、后窗都做成薄板（`slab`）。
- **几个零件叠在同一位置时**（比如表针的针毂和指针本体），把它们放在相邻的高度上，刚好贴合。

### 5.3 运动
- 竖直轴转动（齿轮、摆轮、摆陀、表针）用 `turn` 组，可以转任意角度，而且最省性能。其他轴的转动（车轮绕 x 轴、风扇绕 y 轴）用 `hinge` 组，范围设大一些，比如 `[-36000, 36000]`。
- 特性通道在 `film.mjs` 的 `featureValues` 里由同一个模型算出所有组的角度。`features` 列表里要放几组有代表性的姿态，构建时会验证这些姿态下的绘制顺序。
- 要在镜头里拿掉某个组件（比如掀开后盖和摆陀、看机芯内部），可以加一个 0 到 1 的通道，在 `featureValues` 里把那个组件的滑移量设成 `max(拆开值, 通道 × 距离)`。

### 5.4 拆开的顺序
- 沿同一方向移动时，在前面的零件先走、走得更远：往上拆时，最上面的零件 `delay` 最小、`travel` 最大。
- 用 `scan-apart` 从五个角度扫描。报出的每一对零件都要改，改 `delay`、`travel` 或者高度都可以，不要靠调绘制顺序来掩盖。
- 包住整个物体的外壳（表壳）可以朝反方向退出（往下掉），机芯往上拆，这样就不会互相碰到。

### 5.5 画在零件表面的图案
- 平面图案（`T.plane`）**不会被零件轮廓裁剪**。条纹、刻线如果画超出零件边界，就会悬在空中。要先在代码里把线段裁到零件的多边形里（`stripes(poly)`），再画。
- 表盘这类朝下（−z）的面，图案的 u 方向要镜像（`u = [-1, 0, 0]`），这样从表盘那一面看，12 点还是在上面。
- 表冠要放在 −x 方向，这样从表盘那一面看才在 3 点钟。物体的左右要按“从主要观看的那一面看”来定。

### 5.6 会变形的零件和中间姿态
- **弯曲的薄片**（折叠屏的叠层、皮带、软管）：把它切成一串小块，沿同一条曲线摆放，每一块都是凸零件。曲线由一个 0 到 1 的通道（比如 `fold`）决定，所有小块的位置都从这个通道算出来。
- **干涉检查要覆盖中间姿态**：铰链、折叠这类连续变化的机构，在 0、0.25、0.5、0.75、1 这几个姿态都要检查：把这几组姿态放进 `geometry.mjs` 返回的 `features`，构建时会逐个验证（拆开过程已经自动按 10 个进度采样）。不能只查起点和终点，中间姿态最容易穿插。
- **需要同时看局部和整体时**，用同一个模型多渲染一段全景，合成时用 ffmpeg 的 `overlay` 叠成角落小窗，两段用同一份关键帧，动作自然同步。不要另外画一个简化的替身当小窗。

## 6. 替代方案：没有 anatomy 时用 Three.js 按同样的方法做

1. 按第 2 节的要点写规格单和零件清单（同样 100–150 个零件，按装配关系分组）。
2. 每个零件都是一个独立的 Mesh，用真实尺寸。材质用纸面风格：`MeshToonMaterial` 或 `MeshLambertMaterial`，四档明暗，加 `EdgesGeometry` 描线。背景用 `style.json` 里的 paper 色。
3. 拆开：每组零件有一个拆开方向和距离，用参数 `apart(t)`（0 到 1）插值，外层的零件先动。
4. 机位：`camera(t)` 用关键帧插值，节奏仿照 anatomy-reveal 的 `shots.md`：慢慢漂移、快速甩镜（约 0.24 秒）、短暂停留。
5. 特性零件和读数都由同一个模型驱动。
6. 用 `capture_frames.mjs` 渲染，创建 renderer 时要设 `preserveDrawingBuffer: true`。
7. 检查：从五个角度截图，看拆开过程中有没有零件互相穿过；放大 4 倍看细节。
