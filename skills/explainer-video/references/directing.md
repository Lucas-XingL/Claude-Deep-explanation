# 导演：把讲解变成画面

研究决定能讲什么，脚本决定观众为什么一直看下去，分镜决定每一刻观众看见什么、理解有什么变化。这份文件讲后两件事里最容易出错的地方。第 4 步写脚本、第 5 步做分镜、第 7 步做镜头时都要用到。

## 1. 先写主线：问题、主线、回答

在 `storyboard.json` 的 `meta` 里写三句话：

```json
"meta": {
  "question": "它到底是怎么做到的？真的能飞吗？",
  "throughline": "抓地力有上限 → 风扇把车吸在地上 → 推进器干脆不靠轮胎 → 算一笔气量账",
  "answer": "能离地几秒钟，离持续飞行还很远；推力和气量都还只是工程师的说法"
}
```

- **主线不是章节标题的列表**，而是一条推理链：每一环都是上一环引出的问题。
- **每个镜头都要带来新东西**：新信息、新证据、一个转折，或者一段必要的停留（让观众读完一张图）。写在镜头的 `new_info` 字段里。写不出来的镜头，删掉或者和相邻镜头合并。
- **母版资产重复出场时，要带回新东西**：新的状态、新的证据、新的尺度或新的含义。“换个裁切”“换个颜色”不算。机械表样片里机芯出现了两次：第一次是整块表在走，第二次拆掉摆陀、推近擒纵，讲的是“为什么能走得准”。
- **用户要“更丰富”时，先找缺的讲解环节，不要先加图。** 可以补的有：一个具体例子、一个过程步骤、一组可比的证据、一个因果条件、一个取舍、一个反例、一个后果。只加这个选题需要、并且有来源的。加了以后超长，就合并重复的结论或者缩小承诺，不要靠加快语速、缩短读图时间来塞。

## 2. 每个镜头的画面配方

动手之前，每个镜头回答四个问题，写进分镜的对应字段：

| 字段 | 问题 | Roadster 样片 S02（推力测力台）的答案 |
|---|---|---|
| `subject` | 观众这一刻该看哪个东西？ | 停在测力台上的车 |
| `relation` | 这几句口播讲的是什么关系？（见第 3 节） | 力的比较：推力和重力 |
| `change` | 画面上什么在变，从什么变成什么？ | 推力条从 0 涨到 80 kN（宣称） |
| `result` | 变化的后果在画面的哪里看得见？ | 测力台读数降到 0，车和地面之间出现缝隙 |

`result` 最容易漏。只有 `change` 没有 `result` 的镜头，观众看到东西在动，却不知道动了以后怎样。

## 3. 关系和画法

先判断口播讲的是哪种关系，再选画法。

| 关系 | 这样画 | 别这样画 |
|---|---|---|
| 因果链 | 沿着链条一节一节动起来，前一节的动作引发后一节，最后停在后果上 | 一排方框加箭头同时出现 |
| 对比 | 并排放，同一尺度、同一参照物，只让不同的地方不同 | 两张比例不同的图 |
| 尺度和数量级 | 放到观众熟悉的参照物旁边：头发、胎压、车重线 | 只写一个大数字 |
| 过程和步骤 | 同一个画面里状态逐步变化，一步对应一句口播 | 每一步换一张新图卡 |
| 结构和组成 | 剖解拆开，按真实的装配顺序 | 平面方块图 |
| 力和运动 | 力箭头画在作用点上，物体相对一个固定参照移动 | 用镜头移动代替物体移动 |
| 时间和演变 | 按比例画的时间轴，镜头沿着轴走 | 年份等距排开 |
| 选择和取舍 | 几个选项并列，选中的亮起，没选的变暗但保留 | 只画选中的那一条 |
| 不确定和区间 | 区间条、虚线、范围读数，标“估算”或“宣称” | 一个精确到小数点的数字 |
| 证据链 | 原始材料（照片、文件、数据）入画并标出处，再画推理的步骤 | 只有一张结论卡 |

**内容结构和视觉风格分开定。** 每个镜头必须表现什么关系，由内容决定；纸面风、水彩还是档案风，由用户的选择和 `style.json` 决定。换风格不改变每个镜头要讲清的东西，也不要让风格反过来决定镜头，比如选了 3D 就把图表和年报做成漂浮在空中的展板。

## 4. 镜头的语法

- **先交代在哪，再靠近细节，然后看动作，最后停在后果上。** 机械表样片的顺序是：表盘在走 → 翻过来露出机芯 → 推近擒纵 → 2D 慢放“冲击” → 停在“滴答”。
- **一个场景可以跨好几句口播。** 不要每换一句话就清空画面、把镜头拉回全景。跨句子的连续镜头，在句子交界处机位、构图和主体位置都要连续。
- **长镜头和停留往往比密集的切换更适合讲解。** 没有“每句话几个镜头”“每分钟几个动效”的指标。
- **切镜要有理由**：换到更近的尺度、换到同一个对象的另一面，或者换到上一个镜头引出的东西。在分镜的 `notes` 里写一句为什么在这里切。
- **不要每一段都是“标题卡 → 图卡 → 结论句”的固定节拍。** 段落名最多以角落的 Fig 编号出现。
- **文字是标签和读数，解释交给口播和字幕。** 一屏只有一个重点。

## 5. 常见的画面错误

| 错误 | 为什么不行 | 改法 |
|---|---|---|
| 讲动作时，对着一张照片推近 | 推拉不会让照片里的东西动起来，观众看不到“拨开”“咬合” | 用能动的模型或图解来演这个动作 |
| 把同一物体的两个姿态叠化 | 叠化的中间会出现两只手、两套零件 | 用同一个物体的连续状态来演 |
| 随手连线、画箭头、调大小 | 图形本身就是主张：箭头表示因果或流向，连线表示有关系，大小表示数量 | 没有证据的关系不连线；不成比例的大小标“示意” |
| 模型在动，就以为关系讲清了 | 车轮在转，观众并不知道抓地力已经到了上限 | 加剖面、读数或受力箭头，把关系画出来 |
| 因果链停在半路 | 只演到“阀门打开”，后面的事观众要自己猜 | 走完：阀门打开 → 气沿管路流 → 喷口喷出 → 反作用力 → 车加速或离地 |
| 离地、位移没有固定参照 | 镜头移动和物体移动看起来一样 | 画地面线、测力台、刻度，让参照物不动 |
| 为了看清放大了动作，却没说 | 观众会以为真实的位移、角度、速度就是这样 | 读数里写“示意，未按比例”或慢放倍数（样片写“慢放 1/16”） |
| 零件的变换顺序颠倒 | 零件会绕着错误的中心转 | 先在零件自己的坐标里转，再随组件移动、拆开 |
| 模型超出了适用范围还在用 | 风扇吸地的模型只在车底贴地、密封时成立，车离地后就不成立 | 超出范围时画面上写“这个模型不再适用”，读数归零或变灰，不要外推 |
| 画了模型没算的东西 | 没有模拟轮胎接地时的反力，却画出车在地上被推力推得转动 | 把“想要的姿态”和“画出来的姿态”分开：模型没算的，就不画 |
| 过程动画比口播先播完 | 后半句口播只能配一个静止的结果 | 用 `during` 让动作持续到那句话结束，或者循环当前这一步 |
| 动画抢在口播前面 | 答案先出现，口播再讲就没有悬念 | 结果在说到它的那一刻才出现（`atLine`） |
| 口播在往下讲，画面停着 | 观众看到的是一张幻灯片，注意力就掉了 | 每句话至少有一处画面变化：读数、高亮、箭头、状态或机位。确实要停留（读一张图）就在分镜里写 `hold` 和理由。`check_sync.py` 会逐句查 |
| 同一个主体，在不同镜头里画得不一样 | 3D 里是一辆车，2D 里换成另一辆车的轮廓，观众会以为是两个东西 | 所有镜头里的主体都来自同一个母版资产：2D 场景用 `sprite.sh` 从 3D 模型抠图；人物、产品照片用同一张图的不同裁切 |
| 主体模型只是一个外壳 | 口播说到的部件看不见，“剖解”就只剩一个名字 | 说到的部件都要在模型里，说到时拆开、剖开或推近给观众看 |
| 把一个数字用成了别的量 | 宣称的总推力被画成“向上的推力”，“峰值功率”被画成“持续功率”，结论跟着错 | 按事实表的“口径”用数字。要换算成别的量，就是我们的假设，画面标“示意”或“估算” |
| 描述事件时改了说法 | “沿弯道开到倒挂”被写成“倒扣着开过墙”，事实就变了 | 描述发生了什么的句子，照来源的说法写，并带事实编号 |

## 6. 画力的镜头逐条检查

- [ ] 箭头起点在作用点上，方向对，画在**受力的那个物体**上。
- [ ] 作用力和反作用力在**两个不同的物体**上：喷口把气推向后，气把车推向前。不要把这两个箭头画在同一个物体上，看起来像互相抵消。
- [ ] 分力和合力分开画，不要两套都用同样的箭头。
- [ ] 箭头长度要么按比例（画刻度），要么标“示意”。
- [ ] 喷流和反作用力同时出现、同时消失。
- [ ] 力平衡时物体不动（测力台读数可以变），合力向上才离地。
- [ ] 推力不过质心会产生力矩，物体会转。讲“稳定”“姿态控制”时要画出这一点：能离地，不等于能稳住。

## 7. 先看风格帧，再批量做

全片镜头动工之前，先做 2–3 张**风格帧**，挑不同类型的素材同时出现的画面：anatomy 3D 加 2D 图解、档案照片加数据图、插画人物加时间线。检查：
- 纸面、线条、配色、字体是不是同一套（`style.json`）；
- 视线是不是先落在主体上；
- 信息层次：主体 → 读数 → 角标 → 字幕。

只看同一张图的不同裁切，发现不了风格冲突。两支样片里，2D 场景都用了和 anatomy 同一套 `paper.css`，所以能接在一起。

## 8. 高风险镜头的预检

分镜里给每个镜头标上 `risks`，可以是这四种：

| 风险 | 怎么检查（用 `capture_frames.mjs --stills t1,t2,…` 出指定时刻的帧） |
|---|---|
| `key_action` 关键动作 | 动作的前、中、后各看一帧：动作真的发生了，后果看得见 |
| `continuity` 跨句连续 | 每个句子交界处的前后各看一帧：机位没有跳回去，主体没有跳位置 |
| `occlusion` 遮挡 | 标签、箭头、读数没有被零件挡住，绘制顺序正确 |
| `image_visibility` 素材可见 | 图片加载出来了，主体能认出来，没被裁掉或压暗 |

预检发现的问题修好以后再正式渲染。正式渲染后仍然要从 `clip.mp4` 里抽帧看（见 `verify.md`）。

## 9. 配音定稿后，倒过来查一遍

时间轴定下来以后，对着 `audio/timeline.json` 把全片再过一遍：

1. **逐句对画面**：说到 X 的那一刻，X 在画面上吗？是不是被高亮或者正在动？
2. **只看画面**（看接触表，不看字幕）：大致能不能回答开头的问题？
3. **找“口播在讲新东西、画面在重复”的时段**，比如同一张头像、同一台设备、同一根线停了很久。先判断缺的是什么：
   - 缺解释：补有来源支撑的内容；
   - 缺能看的东西：换成相关的素材或具体的情境；
   - 同一个场景能讲清：给它加状态变化；
   - 本来就没有新内容：删短。

   单纯的推拉、镜像、换色、加装饰都不算新信息。也不要为了“多样”插入和主题无关的画面。
