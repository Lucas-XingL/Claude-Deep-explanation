# R1 剖解路线：anatomy 方法

用户要求用 anatomy 做的选题（比如 Roadster）必须走这条路线。用户选了 R1 的选题（比如机械表、折叠屏铰链、土星五号）也走这条路线。

## 1. 两个现成的 skill

| skill | 作用 | 在这里怎么用 |
|---|---|---|
| **anatomy**（[wheresryan22/anatomy](https://github.com/wheresryan22/anatomy)，MIT） | 等距 SVG 剖解图，可以交互，零件很多、很精细；带 WebGL 特效（火焰、尾焰、水、灯光）；有一套几何检查（`--audit`），保证零件互不穿插 | 学它的方法（第 2 节）；做**可交互的剖解网页**，可以作为额外交付物用于传播；尾焰之类的特效参考它的 `raptor-engine` 示例和 `references/webgl.md` |
| **anatomy-reveal**（[annnguyentt/anatomy-reveal-skill](https://github.com/annnguyentt/anatomy-reveal-skill)，MIT，基于 anatomy 的工具包） | 把一个物体按真实尺寸搭成可以转动、拆开的模型，输出**剖解揭示短片**（MP4，30 fps，3–60 秒，比例可选 9:16、4:5、1:1、16:9，纸面风格，带运动模糊） | **R1 镜头的主要生产工具**：每个 R1 镜头就是一段 anatomy-reveal 短片 |

安装（任选一种；Codex 等其他 agent 的安装目录见各自的 README）：

```sh
# anatomy
npx skills add wheresryan22/anatomy -g -a claude-code
#   或者 git clone https://github.com/wheresryan22/anatomy.git ~/.claude/skills/anatomy
# anatomy-reveal
git clone https://github.com/annnguyentt/anatomy-reveal-skill ~/.claude/skills/anatomy-reveal
```

依赖：Node.js 20+、Chrome 或 Chromium（找不到时设置 `CHROME_PATH`）、ffmpeg、ImageMagick 7（`magick`）。

**用之前先读它们的 SKILL.md 和 references**（anatomy 的 `craft.md`；anatomy-reveal 的 `inputs.md`、`objects.md`、`object.md`、`shots.md`），按它们的规则来做。本文件只讲怎么把它们接进讲解视频的流程。

如果这两个都装不上（比如没有网络），就按第 5 节用 Three.js 按同样的方法自己做，并告诉用户用的是替代方案。

## 2. 方法要点

1. **物体本身就是解释。** 不画方框加箭头，而是找一个真实、做工精良的物体，让它的运作方式本身就是要讲的概念。读者能认出这台机器，也就看懂了道理。
   - 讲“离地需要推力不小于重力”，就画一个推力试验台：车放在台上，秤和推力计的读数随推力变化。
   - 讲“齿比决定转速”，就画一对真实的齿轮（见 `examples/mini`）。
2. **先找真实数据。** 尺寸、数量、阈值、曲线都要真实。读数、运动和说明文字由同一个纯函数模型驱动。
3. **零件要多、要真实。** 每个零件都得有作用，并且安装在另一个零件上；不要为了好看加装饰。放大 4 倍看，每个区域都还有真实的细节可看。
4. **按真实的拆法分组。** 拆开的顺序就是这个东西在工作台上实际拆开的顺序，外面的零件先拆。
5. **一到两个特性零件真的会动。** 选这个东西最核心的动作，比如开合、旋转、按压、喷射。
6. **事先定好规模。**
   - Figure：40–80 个零件。
   - Hero：100–150 个零件，2–4 小时。
   - Epic：整辆车、整栋建筑这种级别，6 小时以上，不要直接做。先给用户一个 Hero 版本：保留核心，细节只花在镜头会推近的 2–3 个区域，其余部分做成干净的大零件。

## 3. 接入讲解视频

1. **规格单**：按 anatomy-reveal 的 `references/inputs.md` 写，包括尺寸、材料、会动的部分、内部结构、按装配关系分组的零件清单、特性零件。来源和证据等级同步写进 `research/facts.md`。
   - 不确定的尺寸要写明假设。
   - 有疑问的地方先给用户看规格单再动手。
2. **搭物体**：
   - `node <anatomy-reveal>/scripts/new-project.mjs scenes/_shared/<物体名>`；
   - 改 `object/geometry.mjs` 和 `object/film.mjs`；
   - 按它的 SKILL.md 做多角度截图和穿插检查（`scan-apart`），直到没有零件互相穿过。
3. **每个 R1 镜头单独出一段短片**：
   - 镜头时长从 `audio/timeline.json` 里取，作为 `--duration` 参数；横版主片用 `--ratio 16:9`，竖版剪辑用 `9:16`；
   - 编排 `motion/timeline.mjs`。节奏按它的 `references/shots.md` 来：慢慢漂移、快速甩镜到下一个主体、短暂停留。转到哪个零件、在哪里推近、什么时候拆开，要和这个镜头的口播对应上；
   - 它的模板只有一份 timeline。做多个镜头时，可以为每个镜头复制一份 `motion/` 目录（比如 `motion-S05/`），也可以每次渲染前替换 timeline，具体看它的 `motion/build.mjs` 支持哪种方式；
   - 渲染命令：`node motion/render.mjs blur …`，然后 `node motion/encode.mjs …`。把结果拷贝到 `scenes/<id>/clip.mp4`；
   - 它的短片没有声音，声音在 `assemble.py` 合成时统一加。
4. **标注和角标**：anatomy 风格要求画面里尽量少字（最多一个刻印小标签）。零件名称、读数解释、证据角标放在镜头四角的卡片位置，或者用 R2 叠加层在合成前加上：用 `capture_frames.mjs` 渲染一个透明背景的 HTML 叠加层，再用 ffmpeg overlay 合进片段。字幕负责其余的说明。
5. **额外交付可交互剖解页**：anatomy-reveal 的 `object/figure.html`，或者 anatomy 做的交互图。可以发到网上供观众自己拖动、拆解，很适合传播。
6. **默认不画商标**，零件用通用名称标注（电池组、电机、推进器）。用户明确要求忠实复刻时，才画品牌标识，并提醒商标风险（见 `rights.md`）。

## 4. Roadster 选题的完整方案

用户原话：介绍马斯克最新的特斯拉“飞行汽车” Roadster 的设计原理，最终生成便于传播的科普讲解视频。

### 4.1 研究（最重要的一步）
- **先查清最新进展**：最近一次官方发布或演示的日期、内容和原话。区分清楚：
  - 已经公开演示的；
  - 官方书面规格；
  - 马斯克口头宣称的；
  - 媒体推测的。
- **弄清“飞”到底指什么**：悬停、跳跃、短时离地，还是助推加速？推进方式是什么（比如宣称的冷气推进器），有没有公开的数量、推力和位置？
- **车辆本身**：尺寸、整备质量、电池容量、电机布局、加速等宣称数据。逐条标证据等级。
- **查不到的数据不能编**。“已知 / 宣称 / 未知”三栏对照本身就是片子的内容。

### 4.2 计算模型（E 级估算，写成 `scenes/_shared/model.js`）
画面读数、口播里的数字和事实表都从这个模型输出：
- **离地条件**：推力 T ≥ m·g。例如 m = 2000 kg 时，T ≥ 约 19.6 kN（m 要换成研究得到的数值）。
- **如果是冷气推进**：悬停 t 秒需要的推进剂质量约为 m_prop ≈ T·t / (Isp·g0)。冷气推进的比冲 Isp 量级只有几十秒，具体取值要查文献并写明假设。这一项通常就是“能飞多久”的关键约束，值得作为全片的核心推导。
- **如果是电动风扇或旋翼**：用动量理论估算悬停功率，和电池能量、放电能力做对比。
- **稳定和控制**：推力中心和质心的相对位置、需要几个推力点、各自需要怎样独立控制推力。

每个结果都和宣称的数据放在一起对照。估算标“估算”角标，屏幕上写明假设。

### 4.3 物体
- **Roadster 剖解模型**，Hero 级别，约 120–150 个零件：
  - 车身外壳面板、车轮和刹车、电池组、驱动单元、座舱；
  - 宣称的飞行相关硬件：有官方信息的按公开信息画；没有的画成“示意”，用浅色调加“推测示意”角标，不能编造成确定的结构。
- **推力试验台**（anatomy 风格的第二个物体）：车放在带测力计的台架上，读数来自计算模型，推进器喷射用 WebGL 尾焰（参考 anatomy 的 Raptor 示例）。离地条件、推进剂消耗都在这个台架上演示。

### 4.4 分镜（主片 3–4 分钟，16:9）
| 段落 | 路线 | 画面 |
|---|---|---|
| 钩子（约 10 秒） | R1 | 模型翻滚进场，快速拆开再合上，盖上“宣称”角标；第一句就是问题 |
| 已知、宣称、未知（约 30 秒） | R2 | 三栏对照卡，每条带证据等级 |
| 拆开看（约 40 秒） | R1 | 按装配关系逐组拆开；甩镜推近到 2–3 个关键区域 |
| 原理一：离地条件（约 40 秒） | R1 加 R3 | 推力试验台，读数随推力上升，越过 m·g 那条线 |
| 原理二：推力能持续多久（约 40 秒） | R3 加 R1 | 推进剂或能量账，一步一步推导，回到台架上看推进剂罐变空 |
| 原理三：稳定与控制（约 30 秒） | R1 | 推力点和质心的几何关系，一侧推力变化时车身的姿态 |
| 还不知道的（约 20 秒） | R2 | 列出未公开、未验证的部分 |
| 收束（约 10 秒） | R1 | 英雄镜头，回答开头的问题 |

### 4.5 传播版本
- **9:16 竖版，60–90 秒**：前 3 秒直接给最强的画面（拆开或者喷射）加上问题，只保留“离地条件”和“能飞多久”两段，字幕烧进画面，结尾停在英雄镜头。
- R1 镜头用 `--ratio 9:16` 重新渲染，不要从横版裁切。
- 封面：英雄镜头的一帧，加一行问题（不超过 12 个字）。
- 额外交付：可交互剖解页的链接。

## 5. 替代方案：没有 anatomy 时用 Three.js 按同样的方法做

1. 按第 2 节的要点写规格单和零件清单（同样 100–150 个零件，按装配关系分组）。
2. 每个零件都是一个独立的 Mesh，用真实尺寸。材质用纸面风格：`MeshToonMaterial` 或 `MeshLambertMaterial`，四档明暗，加 `EdgesGeometry` 描线。背景用 `style.json` 里的 paper 色。
3. 拆开：每组零件有一个拆开方向和距离，用参数 `apart(t)`（0 到 1）插值，外层的零件先动。
4. 机位：`camera(t)` 用关键帧插值，节奏仿照 anatomy-reveal 的 `shots.md`：慢慢漂移、快速甩镜（约 0.24 秒）、短暂停留。
5. 特性零件和读数都由同一个模型驱动。
6. 用 `capture_frames.mjs` 渲染，创建 renderer 时要设 `preserveDrawingBuffer: true`。
7. 检查：从五个角度截图，看拆开过程中有没有零件互相穿过；放大 4 倍看细节。
